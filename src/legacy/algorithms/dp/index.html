البرمجة الديناميكية (Dynamic Programming)

تقنية حل المشكلات بتجزئتها إلى مشكلات فرعية وتخزين نتائجها لتجنب إعادة الحساب

المفهوم

البرمجة الديناميكية (Dynamic Programming) هي تقنية رياضية وخوارزمية تُستخدم لحل المشكلات المعقدة عن طريق تقسيمها إلى مشكلات فرعية أصغر، ثم تخزين نتائج هذه المشكلات الفرعية في جدول (Memoization) لتجنب إعادة حسابها عند الحاجة إليها مرة أخرى. هذا الأسلوب يحول التعقيد الزمني من أسي إلى خطي أو متعدد الحدود.

مثال من الحياة اليومية

تخيل أنك تريد حساب المسافة بين عدة مدن. بدلاً من إعادة حساب نفس المسافة في كل مرة تحتاجها، يمكنك إنشاء جدول يخزن المسافات بين كل زوج من المدن. عندما تحتاج إلى مسافة معينة، تنظر في الجدول بدلاً من إعادة الحساب. هذا بالضبط ما تفعله البرمجة الديناميكية — تخزين نتائج المشكلات الفرعية لحساب النتائج الأكبر بكفاءة.

متى نستخدم البرمجة الديناميكية؟

هناك شرطان أساسيان يجب توفرهما في المشكلة لاستخدام البرمجة الديناميكية:

١. البنية الفرعية المثلى (Optimal Substructure)

يمكن حل المشكلة الكبيرة من خلال الجمع بين الحلول المثلى للمشكلات الفرعية. بمعنى أن الحل الأمثل للمشكلة يحتوي على الحلول المثلى للمشكلات الفرعية داخله.

٢. المشكلات الفرعية المتداخلة (Overlapping Subproblems)

المشكلة يمكن تقسيمها إلى مشكلات فرعية يتم تكرارها عدة مرات. عندها نقوم بتخزين نتائجها بدلاً من إعادة حسابها — وهذا هو جوهر البرمجة الديناميكية.

الطريقتان: Top-down vs Bottom-up

من الأعلى للأسفل (Top-down / Memoization)

نبدأ بالمشكلة الأصلية ونقسمها بشكل عودي إلى مشكلات فرعية. نخزن نتائج المشكلات الفرعية في مصفوفة (Memo) ونسترجعها عند الحاجة.

function fib(n, memo = {}) {
  // حالة أساسية
  if (n <= 1) return n;
  // إذا كان المحسوب موجودًا، استرجعه
  if (memo[n] !== undefined) return memo[n];
  // حساب القيمة وتخزينها
  memo[n] = fib(n-1, memo) + fib(n-2, memo);
  return memo[n];
}

من الأسفل للأعلى (Bottom-up / Tabulation)

نبدأ من أصغر المشكلات الفرعية (الحالات الأساسية) ونبني الحلول الأكبر تصاعديًا باستخدام جدول (Table).

function fib(n) {
  let dp = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i-1] + dp[i-2];
  }
  return dp[n];
}

مثال فيبوناتشي — مقارنة التعقيد

بدون DP — عودية ساذجة (O(2ⁿ))

استدعاءات متكررة تعيد حساب نفس القيم مئات المرات.

fib(5) = fib(4) + fib(3)
fib(4) = fib(3) + fib(2)
fib(3) = fib(2) + fib(1)
→ يتم حساب fib(2) ثلاث مرات!

مع DP — خطي (O(n))

كل قيمة تحسب مرة واحدة فقط وتخزن.

dp[0] = 0
dp[1] = 1
dp[2] = dp[1] + dp[0] = 1
dp[3] = dp[2] + dp[1] = 2
dp[4] = dp[3] + dp[2] = 3
dp[5] = dp[4] + dp[3] = 5

مثال العملات المعدنية (Coin Change)

مشكلة العملات المعدنية: لدينا عملات بقيم معينة (مثل ١، ٥، ١٠، ٢٥) ونريد معرفة أقل عدد من العملات لتكوين مبلغ معين. الحل باستخدام DP:

معادلة DP

dp[0] = 0
dp[amount] = min(dp[amount - coin] + 1) لكل coin ≤ amount

مثال: عملات [١، ٣، ٤]، المبلغ ٦ ← الحل الأمثل = عملتان (٣ + ٣)

مميزات وعيوب البرمجة الديناميكية

المعيار الشرح
مميز يقلل التعقيد الزمني بشكل كبير — من أسي O(2ⁿ) إلى خطي O(n) أو متعدد الحدود.
مميز يحل مشكلات معقدة يصعب حلها بالطرق التقليدية (مثل المسارات الأقصر، الحقيبة، التقطيع).
مميز يقدم حلاً منظمًا وواضحًا بخطوات متسلسلة يمكن تتبعها بسهولة.
عيب يستهلك ذاكرة إضافية لتخزين جدول DP (عادة O(n) أو O(n × m)).
عيب ليس كل المشكلات يمكن حلها باستخدام DP — تحتاج إلى توفر الشرطين الأساسيين.
عيب قد يكون تصميم معادلة DP صعبًا ويتطلب فهماً عميقاً للمشكلة.
